# MAJORINS 複数ケーキ注文・送料無料 仕様メモ

作成日: 2026-08-31  
ステータス: **注文ページ UI 配置済（`/order/`）。Worker `POST /checkout` は未実装**

---

## 1. 背景

平石さん要望のうち、以下は **現行の Stripe Payment Link だけでは実現できない**。

| 要望 | 現状 |
|---|---|
| 複数ケーキを **1回の決済** で注文 | Payment Link は **商品1種類／リンク1本** |
| 商品合計 **1万円以上で送料無料** | Payment Link は **送料固定**（条件分岐不可） |

そのため、**サイト側で注文内容を確定 → 決済処理のみ Stripe** へ渡す構成に移行する必要がある。

> **現時点の運用方針:** 上記は **未実装のまま維持**。ご利用ガイドの「1万円以上送料無料」は **コメントアウトのまま** 公開しない。

## 2. 採用方針: 注文専用ページ（パターン B）

商品紹介は既存トップのショーケースのままとし、**注文専用ページ**（例: `/order/`）を新設する。

| パターン | 内容 | 採否 |
|---|---|---|
| A | トップのショーケースに数量・まとめ注文を追加 | 見送り |
| **B** | **注文専用ページ**（`/order/` 等）で3商品を選択 | **採用** |
| C | 商品紹介ページと注文ページを完全分離 | 見送り（情報量が増えた段階で検討） |

**UIデザインは別途（クライアント側）で作成する。** 本ドキュメントは機能・データフロー・技術方針のみを定義する。

## 3. 決済フロー（確定イメージ）

```
[shop.majorins.jp/order/]
  ユーザーがケーキ種別・数量を選択
  商品合計・送料（1万円判定）・SOLD OUT を表示
       ↓ 「購入する」
[Cloudflare Worker]  POST /checkout
  在庫チェック（週次10個/SKU）
  商品 line_items・送料を確定
  Stripe Checkout Session 作成
       ↓ リダイレクト
[Stripe Hosted Checkout]
  カード決済・配送先・備考（のし等）・メール
       ↓ 決済完了
[Cloudflare Worker]  POST /webhook（既存）
  checkout.session.completed → KV 在庫カウント
       ↓
[サイト] 完了画面（success_url）
```

### 役割分担

| 担当 | 決めること |
|---|---|
| **サイト（/order/）** | 商品選択・数量・合計表示・購入ボタン |
| **Worker** | 在庫可否・送料計算・Checkout Session 作成・在庫更新 |
| **Stripe** | 決済・住所収集・備考欄・レシートメール |

## 4. 現行構成との違い

| | 現行（Payment Link） | 将来（Checkout Session） |
|---|---|---|
| 導線 | ケーキごとに `buy.stripe.com/...` へ直行 | サイトで選んでから Stripe へ |
| 複数ケーキ | 不可（決済が分かれる） | 1回で可能 |
| 送料 | 固定 1,300円（クール便） | 合計に応じて 0 / 1,300 |
| 在庫 SOLD OUT | Worker `/status` + フロント表示 | 同上 + checkout 前にサーバー側でも拒否 |
| のし・備考 | Payment Link カスタム項目（**設定済み**） | Checkout Session の `custom_fields` で同等 |
| レシート | 入力メールへ Stripe から送信 | 同左（請求書発行は **不要**） |

## 5. 送料無料ルール（未確定 → 平石さん確認待ち）

ガイド掲載・実装の前に、以下を確定する。

| # | 確認事項 | 推奨案（EC一般的） |
|---|---|---|
| 1 | 1万円は **税込** か **税抜** か | **税込**（表示価格 4,800円ベース） |
| 2 | クール便と常温が別配送の場合 | **配送単位**で判定（クール合計1万／常温合計1万） |
| 3 | クーポン 300円引き **前** か **後** か | **割引前の商品小計** |
| 4 | 何を1注文と数えるか | **同一 Checkout の line_items 合計** |

### 現行カタログでの数字

- ケーキ単価: **4,800円（税込）**
- 1個 → 4,800円（1万円未満）
- 2個 → 9,600円（未満）
- **3個 → 14,400円（初めて1万円超）**

複数 **種類** を1回で買う場合（例: ノワール1 + パッション1 = 9,600円）は、2種類でも1万円未満。**種類を跨いだ注文** がないと送料無料はほとんど発動しない点を平石さんと共有すること。

## 6. 技術実装の最短ルート

既存 **`workers/stock/`**（在庫 Worker）を拡張する。

### 追加エンドポイント（案）

| メソッド | パス | 役割 |
|---|---|---|
| `POST` | `/checkout` | 選択商品・数量を受け取り Checkout Session URL を返す |
| `GET` | `/status` | 既存（在庫・受付時間） |
| `POST` | `/webhook` | 既存（在庫カウント） |

### Checkout Session 作成時の処理（案）

1. `noir` / `verdant` / `passion` と数量を検証
2. `/status` と同ロジックで受付時間・在庫を確認
3. 商品小計を計算（確定ルールに従う）
4. 小計 ≥ 10,000 → 送料 0、未満 → 1,300（クール便）
5. Stripe Price ID を line_items に設定
6. `shipping_address_collection`（JP）、`custom_fields`（備考）、`allow_promotion_codes` 等を設定
7. `success_url` / `cancel_url` を `/order/` 基準で返す

### サイト側（/order/）

- 3商品の数量選択 UI（**デザインは別途**）
- Worker `/status` で SOLD OUT・受付時間外を反映
- 「購入する」→ Worker `/checkout` → Stripe へリダイレクト

### Payment Link との関係

- 移行完了までは **既存3リンクを残すか、/order/ へ誘導に切り替えるか** を実装時に決定
- 移行後はショーケースの購入ボタンを `/order/`（または種類プリセット付き `/order/?cake=noir`）へ変更

## 7. Stripe に「カート」はあるか

**ない。** カスタムサイト向けの組み込みショッピングカートは提供されない。

- **Payment Link** … 事前設定の決済ページ（条件付き送料不可）
- **Checkout Session** … API で都度作成（**本件はこちら**）

フルECのカート（保持・複数ページ）は不要。**注文専用1ページ + 数量選択** で足りる。
